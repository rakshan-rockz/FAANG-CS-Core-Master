# Phase 4 — OS: CPU Virtualisation

OSTEP chapters 4–10. How one CPU becomes the illusion of many: the process abstraction from the kernel's
side, limited direct execution, context switches and scheduling policies from FIFO to Linux's CFS/EEVDF.
This is the first of the four OS phases that "core subjects" rounds probe hardest.
**Xref:** Phase 3 did fork/exec/wait/signals/syscalls from the program's side (spiral, don't repeat).
SD 0.3.1 treats processes vs threads and context-switch cost at design level; SD 0.3.3 thread pools vs
event loops. The LLD course (sibling repo, if present) owns concurrent class design; this phase owns the
mechanism.
**Reading:** OSTEP 4–10; Waldspurger & Weihl 1994 (lottery); Linux `Documentation/scheduler/`.
**This machine:** kernel 5.14 uses **CFS** (EEVDF replaced it in Linux 6.6); hybrid P/E cores make
scheduling experiments interesting: always record which cores you pinned.
