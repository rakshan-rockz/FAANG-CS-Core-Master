# Phase 6 — OS: Concurrency

OSTEP chapters 26–33. From "two threads increment a counter and lose updates" to locks, condition variables,
semaphores, the classical synchronisation problems, deadlock, event-driven concurrency, the C++ memory model
and lock-free basics. Deadlock (Coffman conditions, banker's algorithm) and producer–consumer/readers–writers
are among the most asked core-subjects questions.
**Xref:** Phase 2.3 did coherence and hardware consistency (store buffers, TSO) — 6.4.2 builds the language
model on top. Phase 4 did scheduling (priority inversion). SD 0.3.3 compares thread pools and event loops at
design level. The LLD course (sibling repo, if present) owns applied concurrent class design (thread-safe
classes, concurrency design patterns, executor design); this phase owns the mechanisms underneath (futex,
CV semantics, memory ordering) and the classical theory. DSA's concurrency LeetCode problems are anchors here.
**Reading:** OSTEP 26–33; Drepper 2011 "Futexes Are Tricky"; Boehm 2005; Williams *C++ Concurrency in Action*
2e ch 5; Herlihy & Shavit *The Art of Multiprocessor Programming* ch 3, 10–11 (optional).
