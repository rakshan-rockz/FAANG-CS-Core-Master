# Phase 10 — Databases I: The Relational Model, SQL & Design

CMU 15-445 lectures 1–2 plus Silberschatz for design theory. The relational model and algebra, SQL in real
depth (logical evaluation order, joins, NULL and three-valued logic, subqueries, CTEs, window functions), two
timed SQL problem labs, ER modelling, functional dependencies and normalisation through BCNF and 4NF.
SQL rounds and "normalise this table" questions are standard at the target companies.
**SD overlap map:** SD 2.1.1 (relational basics), 2.1.2 (normalisation vs denormalisation at design level),
2.1.3–2.1.4 (SQL I–II incl. window functions), 2.1.5 (access-pattern modelling). SD uses SQL to model systems;
this phase goes to semantics (why `NOT IN` with a NULL returns nothing, why a window frame defaults the way it
does), formal design theory (closures, keys, lossless decomposition) and interview-grade SQL fluency.
Phase 11 is the engine underneath.
**Reading:** CMU #01–#02; Silberschatz, Korth & Sudarshan *Database System Concepts* 7e ch 2–7; Codd 1970.
**Tools:** Python's built-in `sqlite3` (SQLite 3.34: window functions and recursive CTEs supported) needs no
install; Postgres via `docker run -d --name pg -e POSTGRES_PASSWORD=pg -p 5432:5432 postgres:16` and
`docker exec -it pg psql -U postgres` for Postgres-specific behaviour.
